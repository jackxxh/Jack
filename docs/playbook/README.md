# Verification playbook

This handwritten collection will distill source-audited engineering lessons into reusable, privacy-safe guidance. It is part of the required deliverable, not an optional appendix.

This playbook records reusable, privacy-safe lessons from validation work. Keep receipts immutable, separate integrity from execution claims, and classify failures as environment, candidate, or evidence problems. Vendor software is optional for the file-only chain; never infer launchability from a hash or a skipped check.

| Required source category | Planned public treatment |
| --- | --- |
| Known failure signatures | Observable symptom, evidence that distinguishes likely causes, bounded recovery, and the check needed before retrying |
| Gap ledger | Separate implemented capability, unavailable evidence, environment prerequisites and explicit non-goals |
| Audit documents | Explain how candidate bytes, tool output, receipts and claim scope are cross-checked; document limits of hash-only trust |
| Checkpoint documents | Capture reproducible handoff and restart checks without private chronology, machine details or raw evidence |

Each final article must identify its sanitized relative source references and distinguish source observations from editorial recommendations. Replace private examples with synthetic ones. Preserve uncertainty and negative outcomes. Do not publish source dumps, machine paths, personal identifiers, network details, raw receipts or proprietary assets.
