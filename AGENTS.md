# Repository working rules

## Isolation

This is an independent public repository with its own Git history and lifecycle. All outputs and temporary working artifacts must stay inside this checkout. Never use an external source workspace's plans, state, goals, automation or delivery gates.

The private source workspace supplied with `--lab` is permanently read-only. The importer reads only a pinned `git archive` snapshot selected by `--source-commit`; it never reads the source working tree. Do not browse it directly, run commands in it, invoke its programs, or create, edit or delete anything there. Do not run its build or tests; build imported files here only. Reject links or path traversal that escape the allowed source or destination boundaries.

If progress would require a source workspace change, stop and report the exact dependency for a human decision. Do not make that change. Do not run source-side Git commands as a shortcut to an unchanged-source claim; the owner may supply that evidence separately.

## One file, one writer

- Handwritten: root README files, LICENSE, SECURITY.md, CONTRIBUTING.md, AGENTS.md, .gitignore, .gitattributes, .github/, docs/playbook/, docs/profile-guide.md, profiles/, samples/ and scripts/import-from-lab.mjs.
- Generated: src/, tests/, tools/, plugins/ and IMPORT_MANIFEST.json. Only the importer may create, replace or remove files here. Never apply manual fixes, formatting or placeholders to generated files.
- Keep generated build output ignored. Do not commit obj/, bin/ or node_modules/.
- A portability change must be a narrow, explicit, audited importer transformation that preserves behavior and records source and output identity. If it cannot preserve behavior, stop for a human decision. Never patch the private source to facilitate publication.
- Curated source documentation used for the playbook must be read through the importer's whitelist. Handwritten playbook articles must be independently sanitized and reviewed; do not copy private audit or checkpoint files wholesale.

## Import contract

The command is `node scripts/import-from-lab.mjs --lab <WORKSPACE_PATH>`.

Compute the import set mechanically from the pinned lab archive: solution projects and each project's Compile/EmbeddedResource/None/Content closure, plus text dependencies discovered by tests. Exclude build caches, private dependencies, vendor binaries, licenses and machine assets. Privacy scanning is a hard gate: report file:line findings and fail rather than silently redacting arbitrary source behavior. Approved transformations and exact loopback/license exceptions must be recorded in the manifest.

Normalize plugin versions by removing local packaging stamps from the source version. Record each generated file's relative source path and SHA-256 in IMPORT_MANIFEST.json, including explicit transformation information when bytes change. Never record private absolute paths. Two imports from identical inputs must produce identical generated bytes, including the manifest. Scan and validate before replacing the generated area; failed imports must not leave a partially published generation.

## Product and evidence

The product is a verifiable evidence pattern for LLM agents; KUKA is the first reference adapter. Files-only users must have a complete no-vendor quickstart of at most three commands. Preserve the distinctions between integrity, static readiness, simulation and virtual native KSS execution. Hashes alone do not authenticate execution or establish physical safety. Never turn a missing, blocked, unsupported or inconclusive check into a pass.

Keep vendor-dependent tests and mark their environment requirements; default CI runs only synthetic Node MCP and pure-logic C# tests. Document the exact skip set. No vendor binaries, license files, proprietary robot assets, virtual machine images or physical-controller operations belong here. Windows bundles may contain the project runtime and redistributable dependencies only.

Do not extract a generic evidence framework before a second real domain adapter exists. Do not introduce extra build systems, package managers or code generators beyond the agreed scope.

## Review and Git

During initial establishment, stop after each stage and wait for the owner's confirmation: repository skeleton, import script, CI, quickstart verification. An unfinished later stage is not a completed acceptance item.

Use a new repository on main. Before the first commit, set repository-local user.name and user.email to the owner's supplied values. Use conventional feat/docs/chore commit messages. The owner creates and authorizes the remote. Authentication, missing-repository or permission errors require stopping and reporting; never bypass them with another identity or access route.

Before the first push, present the final file inventory and IMPORT_MANIFEST.json for explicit confirmation. No push, remote content creation, release publication or tag push may substitute for that confirmation. Do not claim CI is green without a completed remote run, or a clean-clone quickstart without actually running it.

## Build artifacts and runtime

Prebuilt DLLs and all other build outputs are never imported or committed to Git. Stage-three CI must build the imported C# source with the dotnet SDK; the tag Release workflow must build from that source and package the newly built runtime. A bundled runtime is never copied from the private source workspace.
